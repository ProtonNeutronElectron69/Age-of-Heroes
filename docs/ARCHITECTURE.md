# Age of Heroes: Architecture

How the code is organised, how a game flows through it, and where to make common changes. For the rules themselves see [RULES.md](RULES.md); for adding units, abilities and maps see [CONTENT.md](CONTENT.md).

## Packages

```
packages/rules     the rules engine: pure, deterministic TypeScript (no DOM, no Node APIs)
packages/content   game data (units, maps, terrain, scenery, tuning) and the balance model
packages/protocol  online message schemas, the game record (save) format, stateFromView
apps/client        the browser game: React UI, Three.js scene, map editor, online lobby
apps/server        the online game server (Node + ws): rooms, authority, per-player views
```

Dependencies only point downwards: `client` and `server` use `protocol`, `content` and `rules`; `protocol` uses `rules`; `content` uses `rules`; `rules` uses nothing of ours. Workspace packages are consumed as TypeScript source (no build step for packages); the client and server are built with Vite.

## Design principles

- **The engine is a reducer.** `applyCommand(state, command, ctx)` returns `{ ok: true, state, events }` or `{ ok: false, error }` and never mutates its input. Every player action is a `Command`; everything that happened is a `GameEvent` (the log, dice panel and animations read events).
- **Determinism.** All randomness goes through the seeded `Rng` whose state lives in `GameState.rng`. A game is fully described by its setup and command list, so `replayGame(setup, commands, ctx)` rebuilds it exactly. Saves, online resume and bug reports all rely on this.
- **Hidden information.** `viewFor(state, viewer)` removes what a viewer may not see (which of another player's unrevealed tokens is which, the RNG and the dice seed); `hiddenTokens` still says which units hold them, as they stand face down on the cards. The server only ever sends views; `stateFromView` (in `protocol`) turns a view back into a state the client can draw and query.
- **Data-driven content.** Units, maps, terrain, scenery and tunable rule numbers are data validated with zod schemas. Abilities are code, named by id on the cards with numbers in `params`.
- **Line of sight** is computed against simple shapes (terrain prisms, and figure cylinders or, in games with hit zones, each figure's boxes from `hitShapes.json`), never against rendered models, so it is fast and identical on client and server.

## Rules engine (`packages/rules/src`)

| File | What it holds |
|---|---|
| `hex.ts` | Axial hex coordinates (pointy-top): distance, neighbours, rotation, lines, rings, world positions |
| `support.ts` | The balance check that decides whether a piece is held up (centre of mass over its contact points) |
| `shapes.ts`, `board.ts`, `world.ts` | Map pieces (1, 2, 3-line, 3-triangle, 2x2, 7, 24 hexes), the stacked board with bridges, overhangs, scenery and start zones (including which pieces are held up, detached pieces, sealed spaces, start zone hexes that cannot be used, and which pieces form one bridge span), and board-to-world conversion |
| `schema.ts` | Zod schemas for maps and unit cards, and engine-wide limits |
| `terrain.ts`, `tuning.ts` | The shape of terrain rules and tunable numbers (the values live in `content`) |
| `dice.ts`, `rng.ts` | Attack and defense dice, and the seeded RNG (mulberry32) |
| `los.ts` | Line of sight: a strict check from the eye point to the hit band, with terrain, scenery and other figures blocking; with hit zones, `shareInSight` counts how much of a target's body is in sight |
| `hitShapes.ts` | Hit shapes: a figure's boxes (body or gear) in its own frame, read from their stored form (`decodeHitShape`), put on the board (`placeShape`, `shapeFrame`), tested against a line (`segmentHitsBox`) and sampled (`bodySamples`) |
| `game/sight.ts` | Line of sight in a game: what blocks the view (`sightBlockers`: tokens, or figures' boxes with `hitZones`), whether one figure sees another (`figureInSight`), how much of it (`figureShareInSight`) and whether it sees a hex (`spotInSight`). Every check in the engine goes through it |
| `game/combat.ts` cover | `coverFrom` gives the cover of scenery with `cover` (the low wall) to a figure next to it, against an attack from range whose line passes over it. Scenery bigger than one hex (`footprint`, turned by the placement's `rotation`) is stored in every hex it fills, so movement, placement and line of sight treat each hex like one-hex scenery. Scenery with `climb` (the low wall) can be crossed by walking figures at that extra cost: moves pass over it (`placementSpots` and `canStep` with `passing`) but never end on it |
| `editor.ts` | Pure map-editing operations used by the map editor: placing and removing pieces, side placement, start zones, fixing problems, and seeded random fills |
| `game/types.ts` | `GameState`, `Command`, `GameEvent`, `PlayerView` and friends |
| `game/engine.ts` | `createGame`, `applyCommand`, `replayGame`, `waitingOn` and the turn flow |
| `game/draft.ts`, `game/deploy.ts` | Snake draft to a points budget (optionally faction-pure) and deployment. An open draft (`GameSetup.draft: "open"`, online games) lets every player pick at once (`drafters`) with every card exclusive, and deploys one unit each in roll-off order. Zones that grow to fit an army are stored in `GameState.zones`; read a player's zone with `playerZone` |
| `game/rounds.ts` | Token placement, initiative, turn order, wounds, elimination and game over. Under `GameSetup.tokenRule: "onePerUnit"` (new games) each unit holds at most one token and a player places `tokensToPlace` of them; a token left off skips that turn. Older games keep "stack". With `GameSetup.initiative: "players"` (online games) a round waits in the `initiative` phase for every player's `rollInitiative` command before rolling |
| `game/placement.ts`, `game/movement.ts` | Multi-hex footprints, reachable placements (Dijkstra with hazard tie-breaks), moving (in pieces: `ActiveTurn.moves` keeps what each figure has used, and under `zoneOfControl` whether its free step beside an enemy is used and whom it rode through), falling, passing strikes (a `Walk` carried from step to step under zone of control), flying, trample |
| `game/engagement.ts`, `game/combat.ts` | Engagement, attack legality, special actions, mind control, the `power` command (`usePower`: Hurl, Quake Stomp, Fire Breath, Bonecall, Call to Arms), extra attacks (`grantExtraAttacks`) and Lurk (`lurkAttacks`, run after every move) |
| `game/strike.ts` | One attack from dice to wounds (`diceFor`, `resolve`, which returns the wounds dealt): height bonuses, cover, the strike from behind. Shared by `combat.ts` and `movement.ts`, where a Harry passing strike is a full attack |
| `game/facing.ts` | Facing, in games with `config.facing`: a figure's `facing` in degrees (eight directions for a single-hex figure; along its base for a larger one), set at deployment and when a figure is brought back (`faceTowardsMiddle`) and after a move (`faceAfterMove`); the `face` command (`faceProblem`: a figure of the acting unit that has not attacked, or has moved since it attacked, listed in `ActiveTurn.turnable`); and `seesAny`, the front-cone test that `combat.ts` uses for every attack and the strike from behind (`TUNING.behindBonus`; with `strikeFromBehind: "meleeOnly"`, units with a Range of 1 only) |
| `game/glyphs.ts` | Glyphs: `scatterGlyphs` after deployment (seeded, out of start zones, spread out), `pickUpGlyphs` as a turn ends (`endTurn`, with `glyphPickup: "turnEnd"`) or, in older games, at the end of a move (traps spring at once), `useGlyph` (the `useGlyph` command, checked by `glyphProblem`; `summonPlacements` finds spots for the figures a unit brought back has lost, `lostFigures`), `glyphBonus` and `initiativeBonus` for the stat glyphs, and `curseTurnEnded`. All of it is in `GameState.glyphs`, absent in games without glyphs. `viewFor` turns every glyph on the board, and other players' held glyphs, face down (`kind: null`) |
| `game/abilities.ts` | Every ability: attack and defense modifiers, reactions after an attack, end-of-turn effects, special action specs |
| `game/queries.ts`, `game/view.ts` | Read-only helpers (stats, scores, figures; each player's tokens, `tokenIdsFor` and `tokensToPlace`) and per-player views |

Abilities hook in at fixed points: `abilityModifiers` (extra or fewer dice), `targetingProblem` (who may be targeted), `reduceWounds`, `afterAttack` (reactions, with the RNG), `endOfTurnAbilities` (healing, reassembling, and clearing pins), movement (`flying`, `trample`, `smoke-step`, `moveBonus`, pins), forced moves (`forcedMove` in `movement.ts`, used by shoves, pulls and throws) and the special action specs (`AREA_IDS`, `MIND_IDS`, `PULL_IDS`, `SWAP_IDS`, and `POWER_KINDS` for the newer powers). Lasting effects live on the state: `pinned`, `poisoned` (Caustic Spores), `spent` (once-a-game powers), `called` (Call to Arms this round), and on the turn `extraAttacks`, `once` and `callUnit`.

## Content (`packages/content/src`)

- `cards/starter.json` (the first 16 units), `cards/legends.json` (14 more), `cards/reinforcements.json` (18 more, for 48) and `cards/hive.json` (the Sunken Hive, 8 more, for 56); `cards.ts` loads and validates them into `CARDS`, `CARD_CATALOG` and `FACTIONS`.
- `maps/*.json` and `maps/index.ts` (`MAPS`): the premade map library.
- `terrain.ts`, `scenery.ts`, `tuning.ts`, `players.ts` (seat colours), `glyphs.ts` (each glyph's name, colour and mark, and `glyphEffect`, its rules in words).
- `hitShapes.json` and `hitShapes.ts` (`HIT_SHAPES`): each unit's hit zone boxes, one set per pose, made from its detailed model by `apps/client/test/hitShapes.test.ts`.
- `context.ts`: `contextFor(map)` builds the `RulesContext` (board, terrain, cards, tuning, hit shapes) the engine needs.
- `balance.ts`: the balance model that sets point costs (`BALANCE_REPORT=1 pnpm test balance`).

## Protocol (`packages/protocol/src/index.ts`)

- `clientMessageSchema`: create, join, rejoin, spectate, start, command, leave, resume, claim, save, ping. The server validates every message with it.
- `ServerMessage`: welcome (seat and secret token), room, game (view and events; `snapshot` marks a catch-up with the full log), saved (the host's save), ping, watching, error.
- A ping is not a game command: the server passes it to everyone else in the room, at most once a second per player (`PING_INTERVAL_MS`), and never logs, saves or replays it.
- `Replay` / `replaySchema` / `parseReplay`: the **game record** (setup, map, commands, optional name and save time). The same format is a save file and the input for resuming an online game. (The names come from the replay viewer, since removed.)

## Server (`apps/server/src`)

- `server.ts`: HTTP `/health` and the WebSocket at `/ws` (1 MB messages, 40 messages a second, optional origin allow-list, sweeper).
- `rooms.ts`: `RoomManager`, transport-independent and unit-tested. Rooms have 5-letter codes, a host, seats with secret rejoin tokens and spectators. It runs the engine, checks that a player only acts for their own seat, and sends each connection its own view. Rooms live in memory and are cleared 2 hours after the last person disconnects. The host can `save` (gets the full record); `resume` opens a new room from a record, players `claim` their saved armies, and the host continues.
- `index.ts`: reads `PORT` and `ALLOWED_ORIGINS`. The Dockerfile builds a single-file bundle; `render.yaml` deploys it. See [HOSTING.md](HOSTING.md).

## Client (`apps/client/src`)

State lives in small stores read with `useSyncExternalStore`:
- `session.ts`: the game being played. Local (hot-seat) sessions run the engine in the browser; online sessions send commands through `online.ts` and apply server views (`pending` blocks double sends).
- `online.ts`: the WebSocket connection, lobby state, automatic reconnect and rejoin, host save requests, and pings (`sendPing`, `onPing`): spots a player points at with P, passed on by the server outside the game. `scene/Pings.tsx` reads the P key and draws the arrows, on the play screen and the draft map.
- `saves.ts`: named saves in browser storage, summaries and file downloads. `maps.ts`: custom maps in browser storage.
- `music.ts`: the music. `App.tsx` names the scene with `useMusicScene` (menu, play, or victory once the game is over) and the play screen calls `useBattleMusic` while an attack is shown; battle music then stays for `BATTLE_LINGER_MS`. `jukebox.ts` is the player behind it: one `<audio>` element per mood, moved on by `tick(now)` so it can be tested with a clock. It fades the old mood out and the new one in, alternates a mood's tracks with a fade out, a quiet gap and a fade in, and waits for the player's first click when the browser will not play sound yet. `musicTracks.ts` lists each mood's tracks with their composers and licences (the files are in `public/music`), and `ui/MusicControl.tsx` has the on/off box, the volume slider and the credits. Music stops while the tab is hidden.
- `sfx.ts`: the sound effects. `playSound(id)` plays one of a sound's files through the Web Audio API, which starts with the player's first click or key. `startSounds()` (in `main.tsx`) also plays the hover sound for menu buttons and unit cards and the click sound for every button, by listening on the whole page. `useEventSounds` (in `App.tsx`) plays the round and drafted or placed sounds from a command's events; the play screen plays the rest at their moments (each hop's landing through `Figures`' `onLand`, an attack's intro, wounds, destroyed figures), the dice shows play the dice, and `useOnlinePings` plays other players' pings. `soundEffects.ts` lists the sounds, their files in `public/sfx` and their licences, with `pickFile` (random, never the same twice running) and `landingSound` (what a hex's terrain sounds like).
- `testMode.ts`: `TEST_MODE`, set only by the browser tests (`window.__aohTest`). It draws a simpler gaming table and keeps the camera's narrower zoom limits; players never have it.

Screens (`screens/`): `SetupScreen` (the main menu: hot-seat or online setup, saved games, resume, and the Test game that `testGame.ts` builds and loads), `LobbyScreen`, `DraftScreen` (with `DraftMap`, the battlefield it opens on), `PlayScreen` (deployment, tokens, turns, game over), `EditorScreen`. `App.tsx` picks the screen from the session and online state.

The play screen:
- **Unit cards.** The right-hand column shows the acting unit's card (`.unit-card-main`, shown again at each new turn) and below it, smaller, the card of a unit the pointer has rested on for half a second or that was clicked (`.unit-card-other`). `useDelayedHover` keeps the hover card from flickering as the pointer crosses a figure's parts.
- **Camera follow.** A new turn, or a squad passing the selection to its next figure, asks `BoardScene` (its `focus` prop) for a framed glide to that figure, which stops as soon as the player turns or zooms the camera. The glide makes only the parts the player has ticked under Display (Auto pan, Auto rotate, Auto zoom; the request's `parts`); the glide to a fight (every attack) always makes all three, and looks across the line between the two figures so they stand side by side (from whichever side is nearer the current view: the request's `either`). It waits until every figure has finished hopping: `scene/activity.ts` keeps, per canvas, which figures are hopping and whether a glide is due, and browser tests read the latter through `window.__aoh.cameraBusy()`.
- **Hex tooltip.** A middle click on the play or draft board (`BoardScene`'s `onInspect`, a ray cast to the terrain under any figure) opens `ui/HexTip.tsx`: the hex's terrain, elevation, headroom, special rules, scenery and start zone.
- **Glyphs.** `scene/Glyphs.tsx` draws the face-down tiles on the play board, and the pickup (`GlyphPickups`): once the figure that ended its move on a glyph has landed, the tile lifts off spinning and shows its face over the figure, or a question mark to a viewer who may not know it, then fades, while the new glyph glows in the panel; `ui/GlyphPanel.tsx`, in the left column, lists what each player holds (face up only for this device's player, or in hot-seat the player whose turn it is), the stat glyphs in play and the curses counting down. A held glyph's **Use** opens the units it can go on now (`glyphProblem`). For the Glyph of Resurrection (a destroyed unit, or a squad that has lost figures: `lostFigures`) the play screen then shows a Resurrection panel: the player clicks the highlighted hexes (`summonOptions`) for each returning figure, as at deployment, and Confirm sends `useGlyph` with the placements; **Auto place** fills the rest (`summonPlacements` picks the nearest). The hex tooltip says when a glyph lies on the hex.
- **Pings (online).** `scene/Pings.tsx` reads the P key (`PingInput`), keeps the pings on screen (`useOnlinePings`, shared with the draft map) and draws the arcing arrows.

The draft: `DraftScreen` opens on `DraftMap`, the board with each player's start zone in their colour and a name label over it, until the first pick has been made; **View map** brings it back at any time. In an open draft (online) every player picks from the same cards at once, and a card someone has taken shows who took it.

Main menu (`screens/menu/`): `SetupScreen` keeps the menu's state and builds its choices and panels; `MenuFrame` draws them in the player's menu style: War Table, Atlas, Banner Hall or Hex Command (`settings.ts` keeps the choice). Every style has the same choices and the same panel markup (`.mp-*` classes), dressed by `menu.css`. On a landscape window the menu is laid out on a 1280 by 720 stage scaled to fit, so nothing scrolls; a narrow or upright window gets one scrolling column (`.compact`). The bottom right corner shows the version and the last update (`version.ts`): the build takes the version from `apps/client/package.json` and the date from the latest commit (`define` in `vite.config.ts`), so `version.test.ts` checks only how they are written. `MenuBoard` is the War Table's backdrop: the Proving Grounds with six armies, drawn by `BoardScene` (with `still`, so it has no camera controls) and `Figures`, while the camera circles slowly at 30 frames a second.

Scene (`scene/`):
- `BoardScene`: terrain as one instanced mesh per terrain type plus one set of outlines (thin lines in the classic look; wide lines in the detailed look, which draws each terrain with textures painted in code by `tileArt.ts` and made into materials by `tileMaterials.ts`; at High they are painted twice as sharp (`SHARP`: smooth fields scaled up, strokes drawn at full size), the relief is a normal map worked out from the height map (`normalsFrom`), and water and lava move through edited shaders (`flowShaders`, on the `FLOW_TIME` clock that `FlowClock` winds on about 30 times a second while either is on the board); its scenery uses the finishes in `sceneryArt.ts`), scenery, markers, the camera with WASD panning and the follow glide, eye view with drag and arrow-key look-around (kept to the figure's front cone in games with facing, `coneLimits`), and the middle-click inspector.
- `Figures`: figure models on their bases, or tokens with multi-hex figures drawn as one rounded piece over their footprint, as the display setting says (in games with hit zones, tokens are each figure's boxes: `ShapeToken`); plus a single DOM label layer positioned each frame, since per-figure React roots caused unmount errors. A model shares its unit's meshes with the unit's other figures, takes clicks and hovers through a hidden token-shaped target, shows its state with a ring round its base, and is drawn darker once it has acted. A single-hex model faces the nearest enemy figure across a side of its hex; a larger one faces along its base.
- `Pings.tsx` (online pings), `FightFx.tsx` (the attack intro and wound numbers), `activity.ts` (what is moving on a board, so the camera waits for hops, and how many wound numbers, bursts and reactions it has played), `wake.ts` (starting an animation after a rest), `dice3d.tsx` (the dice faces and the initiative d20), `diceRoll.ts` and `DiceTray.tsx` (an attack's throw into the dice tray, below), `Table.tsx` and `tableLayout.ts` (the gaming table, below).
- `lighting.tsx`: the board's light by graphics quality (`BoardLights`): at High a warm key light with soft shadows, a cool fill and a sky light, and each drawn frame marking which meshes cast and take shadows; at Low the plain light it always had.
- `particles.ts` and `Particles.tsx`: particle bursts at High (sparks, a glint off a blocked blow, dust, splashes, embers, a burst as a destroyed figure leaves, a heal sparkle). `particles.ts` is pure: a burst is made from a seed and a particle's place at any moment comes from a closed form. The play screen asks through a `Bursts` queue (dropped while no board draws them), and `Particles` draws every burst as two point clouds, glowing and solid, so two draw calls at most; it draws only while a burst is in the air.
- `reactions.ts`: a figure's reactions in a fight at High, as poses over time (pure): the attacker's lunge (melee) or kick (a shot), a recoil when wounds land, and a destroyed figure's topple. `Figures.tsx` plays them (`FigureReactions`), tipping the drawing about a line on the ground; its click target and name tag stay put.
- `TestHook`: the projection helper, draw call stats camera state, and the graphics in use (`graphics()`: shadows on, meshes casting, bursts and reactions played) for browser tests.

Moving figures (`scene/Figures.tsx`): the rules put a figure on its new hex at once, and only its drawing lags behind. `useFigureAnimation` moves the drawing about the figure's place: it hops hex by hex along a `figureMoved` event's path (`motions`), hangs from the pointer while dragged (`carry`), jumps for the H key (`jump`), and glides after any other change of place. A model's hidden click target stays on the figure's real hex throughout. The play board is drawn only when something changes: each animation asks for frames while it runs (`invalidate`, or `useWake` in `scene/wake.ts` to start one after a rest), and only the decorative loops (the selection arrow's bob, the ready and target rings' pulse) run for good, standing still when the player's system asks for reduced motion. A press on a figure that may act holds the camera still, and moving the pointer then drags the figure; the play screen makes the move when it is let go over a hex it can reach.

The table (`scene/Table.tsx`): `GamingTable` draws the table, its legs and the floor in one of three styles, with wood and cloth painted into canvases in code. `TableCards` lays each unit's card on it, with the figures that are off the board standing on it, as the same models the board draws: those waiting to deploy and those destroyed. This round's activation tokens stand on the cards (`TableToken`, turned to the camera; `tokensOnCards` decides which show their numbers), and stat glyphs in play lie face up on their unit's card (`TableGlyph`, its art from `ui/glyphArt.ts`). The card's picture is the `HexCard` drawing painted into a texture once (`scene/cardTexture.tsx`). `scene/tableLayout.ts` is the pure arithmetic: which side each player sits on, where each card goes, and how large the square table must be; `scene/tableData.ts` feeds it from a game. The play screen draws the table; the editor and the menu backdrop do not.

UI (`ui/`): unit cards, dice overlay, log, the hot keys list (`HotKeys` in `panels.tsx`), round bar, token panel, game menu and save dialog. **The ledger look** (`Ledger.tsx`, styles in `ledger.css`, scoped to the play screen): the left column's panels are parchment sheets with brass buttons. A sheet that names who is acting opens with a `Ribbon` in the player's colour and the unit's faction emblem (`FactionSeal`; its text is the `.turn-banner` tests read), then the chosen figure's `Pills` and a one-line `Hint` that `turnHint` in `PlayScreen.tsx` words from what the figure can do. The log, the glyphs and the keys share one `Drawer` with a tab each; one tab is open at a time, every tab's content stays in the page while hidden, and a glyph pickup makes the Glyphs tab glow. The round track is a wooden strip, and Display, Save and Quit are round icon buttons in the right column's corner (`GameMenu round`), named for screen readers. **Attack effects.** `fight.ts` reads a command's events for the board: who attacked whom and whether from range (`fightIn`, which leaves out blows struck back as a figure falls so the intro gives nothing away), the wounds each figure took (`woundMarksIn`) and where destroyed figures fell (`fallenSpots`); `apps/client/test/fight.test.ts` checks them. `scene/FightFx.tsx` draws the attack intro (`FightIntro`: auras, the arcing arrow, the melee or ranged icon) and the floating wound numbers (`WoundNumbers`), with their textures drawn once on a 2D canvas. The play screen runs an attack as a beat: the intro (`INTRO_MS`), then the dice show if **Dice rolls** is on, then the numbers, then destroyed figures shake (`FigureShake` in `scene/Figures.tsx`) and leave the board; at High graphics quality the attacker lunges (or kicks back as it shoots) during the intro, sparks fly and the wounded recoil as the numbers rise, and a destroyed figure topples instead of shaking and goes in a burst of dust and chips; until then they are drawn where they fell, and kept off their table card. A squad's camera follow waits for the numbers. Online, a click on the intro or the dice sends a `watched` message; the server answers everyone with `watching` (who is still watching that show, named by the event count once the attack happened) and the show ends on every screen once nobody is. Until then the next move is held (`busy`), for at most `HOLD_LIMIT_MS` after this player's own show ends.
`ui/RollShow.tsx` is the dice show on the play screen: `AttackShow` (the full scene, or dice only) for a command's attack rolls, and `InitiativeShow` with a d20 per player. It only shows results the events already hold, except that in online games the initiative show sends the player's `rollInitiative` and waits for everyone's before the dice tumble. In an attack the dice are thrown into a felt-lined wooden tray on a wooden table under a lamp, with soft shadows (`scene/DiceTray.tsx`: `TraySet`, `ThrownDice`, `FrameView`), and the two figures, drawn larger than on the board, stand on the table at the tray's ends. `scene/diceRoll.ts` works the throw out in advance: a small rigid-body simulation of cubes against the felt and the walls, meeting each other as slightly rounded balls so none balances on another, with a knock for a die left leaning. The attack dice are thrown from the attacker's end and settle; then the defense dice are thrown from the defender's end. The recorded paths are played back, and each die's drawing is turned by one of the cube's symmetries (`remapFor`) so it rests on the face the rules rolled. The tray grows with the number of dice. `scene/dice3d.tsx` has the dice faces and the initiative d20, which tumbles and lands on a given number; `apps/client/test/dice.test.ts` checks the landing turns and that every throw lands on the rolled faces, flat, apart and inside the tray. `screens/DiceShowScreen.tsx` is a design page for the show, opened with `?dice` in the address: pick two units and the dice, and roll. **Dice rolls** under Display (`settings.ts`) picks the full scene, dice only or none. The unit card is `ui/HexCard.tsx`: a seven-hex SVG drawing with the name and rules text laid over it and sized to fit, coloured from `ui/factionThemes.ts`, with emblems and stat icons in `ui/hexCardArt.tsx`. Unit art lives in `ui/art/`: a drawing is a list of flat shapes with roles (`types.ts`), built with the helpers in `build.ts`, one file per faction in `drawings/`, collected by card id in `drawings.ts`. `UnitArt.tsx` paints a drawing in the ink and colour style and as the hit zone picture. `ui/UnitCardView.tsx` wraps the card with the enlarge control and the figures left that the screens use. `screens/CardGalleryScreen.tsx` shows every card; open the game with `?cards` in the address.

Figure models (`models/`): each unit's 3D model is built in code from a few solid shapes, so there are no model files to load. Every unit has a classic model in one colour (`UNIT_MODELS`) and a detailed one, painted part by part (`DETAILED_MODELS` in `detailed.ts`, with the colours in `paint.ts`), which the detailed look draws (`unitModel`). Its paints are baked into vertex colours (`bakedGeometry`), so a figure takes one mesh, plus one for parts that glow. `build.ts` has the shapes (`box`, `limb`, `ball`, `spine`, `plate`), and `figure` and `squad`, which size a model so that it and its base stand the card's Height; `human.ts` is a posable person, `horse.ts` a horse, `poses.ts` shared stances, and `gear.ts` shared spears, shields, bows and flight stands; `units/` holds one file per faction, with a model for every card by its id (`units/hive.ts` builds the Sunken Hive's classic and detailed models from the same poses), collected in `index.ts` (`UNIT_MODELS`, `figureGeometry`, `baseGeometry`). `base.ts` makes the base a figure stands on from its footprint: a top and a bevelled rim, with a lobe on each hex and a waist between hexes (rounder at High, with more corners and a bulging bevel). At High, in the detailed look (the classic look stays plain), a figure also keeps its high-only parts (`Part.high`, made with `fine()` in `detailed.ts`), is shaded smooth across gentle bends (`CREASE` in `bakedGeometry`), stands on its faction's ground (`ground.ts`: grass and flowers, flagstones, ash and bones, shells and coral, raked gravel, cartridges and cogs, metal plates, baked into the figure's mesh by `withGround`), and takes an edge light in its player's colour (`edgeLitMaterial` in `scene/Figures.tsx`, unless **Outline glow in player colours** under Display is unticked); Low leaves all of these out. The triangle budget, `TRIANGLE_BUDGET` in `measure.ts`, is 3,000 a figure, ground included. `colors.ts` holds the base's light brown and the three colour schemes (`figureColors`): the model takes the faction's colour, the player's colour or a plain grey, and the rim of the base takes the player's or the faction's colour. `measure.ts` works out how a model sits on the board (`baseFrame`) and how far its body hangs over the edge of its hexes (`measure`, `OVERHANG_LIMITS`). `screens/ModelGalleryScreen.tsx` stands the models on a board; open the game with `?models` in the address. `scene/standing.tsx` lines units up on a display board and draws them; the model page and the unit gallery share it. `screens/UnitGalleryScreen.tsx` is the unit gallery on the main menu: every card in a grid of 5, 3 or 1 across, filtered by faction, type, attack and a search, and sorted by name, faction or a stat. Choosing a card opens its model in a viewer that turns and zooms; that canvas draws on demand, not every frame, so the card grid stays quick. `ui/UnitFilters.tsx` holds its filters and sort, which the draft shares. `screens/MapGalleryScreen.tsx` is the map gallery: each map drawn with `BoardScene`, its start zones marked for a chosen number of players, and its facts beside it. The play screen draws the models on the board (`scene/Figures.tsx`). `settings.ts` keeps each player's display choices in the browser: models or tokens, the colour scheme, the menu style, the gaming table, the dice show, the camera follow boxes and the music; `ui/DisplayMenu.tsx` sets them.

## Client feature notes

What each client feature does and which code holds it. [CLAUDE.md](../CLAUDE.md) keeps the short list of rules to keep; this is the detail behind them. Keep it current with the client in the same pull request as a change.

### State and online
- **Stores:** `session.ts` holds the game in play, `online.ts` the connection and lobby, `saves.ts` named saves, `settings.ts` each player's display choices.
- **Online sends:** online commands set `session.pending` until the server answers; the UI blocks repeat actions meanwhile.
- **Online rules:** the server sets `draft: "open"` (everyone drafts at once, each card once) and `initiative: "players"` (a round waits for every player's `rollInitiative`) in each online `GameSetup` (`apps/server/src/rooms.ts`). Hot-seat games and older saves leave both out and keep the snake draft and the automatic roll.
- **New-game rules:** every new game, hot-seat (`SetupScreen.tsx`), online (`rooms.ts`) and the test game (`testGame.ts`), takes `NEW_GAME_RULES`; `glyphs` (default 4; the test game all 11) is chosen per game.
- **Token rules:** new games set `tokenRule: "onePerUnit"` (one token per unit; `tokensToPlace` is fewer when a player has fewer units) and `tokenAllowance: "half"` (numbered tokens for half the starting army, rounded up, plus X: `tokenIdsFor`, fixed in `state.tokenCounts` as round 1 begins). Token ids are strings ("1", "2", ... and `BLUFF_TOKEN`). Older saves leave them out and keep three numbered tokens, and the oldest "stack" (all four, stacking allowed), so they still replay exactly. Keep them all working.
- **Swamp, zone of control, glyph pickup, strike from behind, engagement:** new games set `swampRoll: "d20"` (the terrain's `endTurnRoll`) and `zoneOfControl` (one free step beside an enemy a turn, kept in `ActiveTurn.moves` with the enemies ridden through by Trample, which make no passing strikes). Older saves leave them out and keep the attack die and the old passing strikes. They also set `glyphPickup: "turnEnd"` (glyphs are picked up in `endTurn` by the acting unit's figures standing on them, not as a move ends), `strikeFromBehind: "meleeOnly"` (no strike from behind for a unit with a Range above 1) and `engagedSpecials` (engagement limits only the normal attack: `Reach.special` in `combat.ts`).
- **Tokens and glyphs on the table:** tokens stand on their cards (`TableToken` in `scene/Table.tsx`, turned to the camera); `tokensOnCards` in `scene/tableData.ts` decides which show their numbers: the viewer's own (online this device's player; on one device the player whose turn it is or who is placing tokens) and revealed ones. A view lists another player's face-down tokens by unit in `hiddenTokens`, and `stateFromView` keeps it. Stat glyphs in play lie face up on their unit's card (`TableGlyph`), with art drawn by `ui/glyphArt.ts`, which the Glyphs panel shares.
- **Pings:** P points at a spot for everyone online, in play and on the draft map (`useOnlinePings` and `PingInput` in `scene/Pings.tsx`). A ping is a protocol message, not a game command: the server passes it on at most once a second per player (`PING_INTERVAL_MS`) and never logs, saves or replays it. The sender's arrow shows at once.

### Drawing the board
- **Graphics quality:** **Graphics** under Display is High (the default, every effect on) or Low (the plainest board, as it was before); `graphics` in `settings.ts`, read through `useGraphics()`. Every new effect checks it, and Low must stay as quick as it is. High lights the board from `scene/lighting.tsx` (`BoardLights`): a warm key light casting soft shadows from a 2048-pixel map fitted to the board, a cool fill and a softer sky light. Each drawn frame marks lit, solid meshes to cast and take shadows (markers, glows, outlines and see-through copies never do; `userData.noShadow` opts a mesh out). Each quality's lights have their own React keys, so switching never reuses a light with the other quality's props. High also paints the detailed tiles twice as sharp, with normal-mapped relief, and moves water and lava (`tileMaterials.ts`; **Moving water and lava** under Display, `flow` in `settings.ts`). Figures at High, in the detailed look, keep their high-only parts (`Part.high`, made with `fine()` in `models/detailed.ts`), are shaded smooth across gentle bends, stand on rounder bases dressed with their faction's ground (`models/ground.ts`) and have an edge light in their player's colour (**Outline glow in player colours** under Display, `outlineGlow` in `settings.ts`); Low, and the classic look (B) at any quality, draw them as they always were. The model page and unit gallery (`scene/standing.tsx`) show the same detail. The `graphics` browser test checks High and runs only when graphics code changes.
- **Drawing on demand:** the play board draws only when something changes (`frameloop="demand"`), so a resting board costs nothing. An animation starts with `useWake()` (`scene/wake.ts`, which also stops the first step covering the whole rest) and calls `invalidate()` each frame while it runs, plus one frame after it stops so the name tags catch up. Only decorative loops run forever (the selection arrow's bob, the rings' pulse, through `useLoop`), and they stand still under reduced motion. Moving water and lava are the other exception: at High, while either is on the board, `FlowClock` (`BoardScene.tsx`) asks for a frame about 30 times a second; they stop under reduced motion, at Low and when the player unticks them. `full-game` fails if a resting board keeps drawing (`window.__aoh.stats().frames`).
- **Moving figures:** a figure's drawing hops, is dragged or jumps about its real place (`useFigureAnimation` in `scene/Figures.tsx`); the state is already final. A model's click target stays on its real hex, so tests can click it mid-hop. Dragging a figure holds the camera still by switching the orbit controls off in the same pointer event.
- **Looks:** the game has two looks, chosen under Display (**Look**; `tiles` in `settings.ts`, the B key in play): detailed (the default) and classic. They cover the tiles, the scenery and the figures. Detailed tiles are painted in code in `scene/tileArt.ts` (a top and a side texture per terrain: colour, relief and glow) and made into materials in `scene/tileMaterials.ts`; a terrain without art keeps its flat colour. Each look keeps one instanced mesh per terrain (`tileGeometry` draws a tile in two parts), and the detailed look's outlines are wide lines in world units (`BOLD_EDGE`). Every tile is turned by a sixth chosen from its hex, so neighbours' textures differ. Scenery follows the same choice: in the detailed look `SceneryMesh` uses the textured finishes from `scene/sceneryArt.ts` (stone, fieldstone, bark, needles, rock, soil; `worldUV` keeps stone one size on any face), a three-tier tree and a lumpy boulder; the classic look and the editor's preview keep the flat colours. Shapes stay within the classic outlines, and line of sight uses the scenery rules, never the model. Figures too: in the detailed look every unit is drawn with its detailed model (`DETAILED_MODELS` in `models/detailed.ts`, picked by `unitModel`), painted part by part; the classic look keeps the classic models. A new unit needs both (the model tests check), though `unitModel` falls back to the classic one.
- **Hit zones on the board:** in games with hit zones each `FigureView` carries its `hitShape`, and the token view (T) draws it (`ShapeToken` in `scene/Figures.tsx`: body boxes in the player's colour, gear grey, one mesh each and cached per shape) where the rules put it (`shapeFrame`). Hovering an enemy with a figure chosen adds the share of its body in sight to the turn's help line (`shareSeen` in `PlayScreen.tsx`).
- **Figure labels:** one DOM layer positioned each frame that is drawn (`scene/Figures.tsx`). Do not go back to drei `Html` per figure; it threw on unmount.
- **Figure models:** built in code in `apps/client/src/models` (see [docs/CONTENT.md](docs/CONTENT.md)). A model matches its card: as tall as its Height with its base, on its footprint, within the overhang limits, and within 3,000 triangles (`TRIANGLE_BUDGET`, ground and high-only parts included). Line of sight never reads a model: in games with hit zones it uses boxes made from the detailed models and stored as data (`hitShapes.json` in `@aoh/content`, made by `models/hitShape.ts`; see docs/CONTENT.md), else the token shape. On the board a model takes clicks through an unseen token-shaped target. `colors.ts` has the three colour schemes; `?models` shows every model. A detailed model gives each part a `paint` (`paint.ts`): `coat` takes the scheme's model colour so armies still read at a glance, and the rest are natural colours or shades of it; the grey scheme paints every part grey. `place()` keeps a part's paint, so the usual builders work. The paints are baked into vertex colours (`bakedGeometry`, drawn by `PaintedModel` in `scene/Figures.tsx`), so a figure is one mesh plus one for glowing parts, whatever its paints: `full-game` holds the board to 300 draw calls.
- **Gaming table:** `scene/Table.tsx` draws it and `scene/tableLayout.ts` places the cards and sizes it; keep the layout pure, it has unit tests. The table must not change the camera: its views and zoom limits (`CAMERA_NEAREST` and `CAMERA_FURTHEST_*` in `scene/BoardScene.tsx`) come from the board alone. The table top is at height 0 and takes no clicks; only the cards do.

### Play screen
- **Camera follow:** a glide to the acting unit (`CameraFocusRequest` in `scene/BoardScene.tsx`), time based, stopped when the player grabs the camera. It makes only the parts ticked under Display (Auto pan, Auto rotate, Auto zoom), except the glide to a fight, which makes all three, and it waits until no figure is hopping (`scene/activity.ts`).
- **Attack effects:** every attack plays a two-second intro on the board (`scene/FightFx.tsx`, read from the events by `fight.ts`), whatever **Dice rolls** says, then the dice show, then wound numbers float up and destroyed figures shake before leaving the board (drawn where they fell until then). At High graphics quality, and not under reduced motion, the play screen adds reactions (`scene/reactions.ts`: the attacker lunges or kicks, the wounded recoil, a destroyed figure topples instead of shaking) and particle bursts (`scene/particles.ts`, drawn by `Particles.tsx`: sparks or a glint as the numbers rise, a burst as a destroyed figure leaves, dust, splashes or embers where a figure lands, a sparkle on a heal). They fit the existing timings, so a fight takes no longer. Low keeps none of them. Online, a click skips only once every player has clicked: the `watched` and `watching` messages, outside the game like pings. The player whose turn it is is held (`busy`) until everyone has finished watching, for at most `HOLD_LIMIT_MS` after their own show.
- **Dice show:** `ui/RollShow.tsx` shows attacks and initiative after the rules have rolled and never changes the game, with one exception: online, the initiative show's button sends the player's `rollInitiative` (with **Dice rolls** set to None, the play screen sends it at once). An attack's dice are thrown into a walled tray (`scene/DiceTray.tsx`), with the two figures standing on the table at its ends, so no die can reach them. The throw is worked out in advance by a small rigid-body simulation (`scene/diceRoll.ts`: cubes against the felt and walls, dice meeting as slightly rounded balls), seeded from the roll, and played back; each die's drawing is then turned by one of the cube's symmetries so it rests on the face the rules rolled. The attack dice settle before the defense dice are thrown and no longer move after that. `apps/client/test/dice.test.ts` checks that every throw lands on the rolled faces, flat, apart and inside the tray. Attack dice are light red and defense dice light blue (`LOOK` in `scene/dice3d.tsx`, and `.die` in `styles.css`). Keep the simulation pure (no DOM). `?dice` in the address opens the show on its own (`screens/DiceShowScreen.tsx`).
- **Ledger look:** the play screen's panels are parchment sheets (`ui/Ledger.tsx` and `ui/ledger.css`, scoped to `.screen.play`, so the editor and draft keep their dark panels). The turn sheet has a ribbon in the acting player's colour with the faction emblem, pills for the chosen figure and one line of help (`turnHint` in `PlayScreen.tsx`); keep that line short and move key lists to the Keys tab. The log, glyphs and keys share one drawer, a tab each (`Drawer`); tests open the Glyphs tab before reading the Glyphs panel.
- **Right panel:** the unit cards, then round buttons for Save, Quit and Display. The cards are sized from the window's height (`--card-room` in `styles.css`) so the buttons always stay on screen; the Display panel opens over the cards. `full-game` checks it.
- **Move markers:** the hexes a figure may move to are green (orange when risky) with a soft glowing ring (`Marker.ring`; `MarkerRings` in `scene/BoardScene.tsx` draws them all in one instanced mesh, so they add one draw call). The rings stand still.
- **Hex tooltip:** a middle click on the play or draft board (`ui/HexTip.tsx`, through `BoardScene`'s `onInspect`); a middle drag still zooms.
- **Glyphs:** face-down tiles on the board (`scene/Glyphs.tsx`) and the Glyphs panel (`ui/GlyphPanel.tsx`) under the drawer's Glyphs tab, whose badge counts the viewer's held glyphs. Held glyphs show face up only to their player (online the view hides the rest; hot-seat shows only the active player's). A glyph's Use lists the units `glyphProblem` allows; the Glyph of Resurrection (on a destroyed unit, or a squad that has lost figures: `lostFigures`) then opens the Resurrection panel, where the player clicks the hexes `summonOptions` offers for each returning figure. A pickup (`glyphTaken`, as the turn ends in new games) plays `GlyphPickups` in `scene/Glyphs.tsx` once the figure has landed: the tile lifts off and shows its face for `PICKUP_SECONDS` (a question mark to a viewer who may not know it; on one device, the player whose turn just ended may), and the Glyphs tab and the new glyph glow. Older saves leave `glyphs` out and have none.
- **Facing:** new games set `facing`; older saves leave it out, have no facing and keep their models turned to the nearest enemy. A figure's `facing` is in degrees (`packages/rules/src/game/facing.ts`, the same turn the client draws a model with). R sends `face` for the figure `turning()` picks in `PlayScreen.tsx` (the chosen one if it may turn, before or after it moves, else the last to move that may), which draws its front cone's outline (`FacingCone` in `scene/Figures.tsx`); for a big figure about to move, R picks its end facing (Move preview); otherwise R still turns a big figure being placed. Tokens show facing with a pointer on the cap. Eye view keeps to the front cone (`coneLimits` in `scene/BoardScene.tsx`). `figureFaced` is left out of the log.
- **Move preview:** hovering a hex the chosen figure may move to draws a see-through copy of it where the move ends, turned the way it will face (`FigurePreview` and `GhostFigure` in `scene/Figures.tsx`), with its front cone in games with facing; `endFacing` in `facing.ts` gives the facing, as `faceAfterMove` will set it. A big figure may end on a hex facing several ways: `optionAt` in `PlayScreen.tsx` takes the one picked with R (`endRotation`, kept while hovering other hexes until the move or a new selection), else the safest, then the one facing most nearly the way it travels. The path finder breaks ties between equally safe and long routes by how natural they look (`better` in `movement.ts`); it changes only the suggested path, never what a move does.
- **Powers and new abilities on the play screen:** the action modes (`specials`, without Call to Arms) cover the new kinds too: a click on a target for Life Tap, Constrict and Circle Cut; Hurl picks the enemy up (`throwing`) and then an orange hex; Fire Breath shows a red hex for each way it may go and the row it burns on hover (`breaths`); Quake Stomp has a button; Bonecall lists the squads it can raise. Call to Arms has its own row of squads on the sheet, Wings of Refuge a carry choice (`carryId`, sent as the move's `carry`), and a Blink move option carries `ability: "blink"` into the move command (`moveCommand`). A figure with an extra attack stays selectable for one more normal attack.
- **Moves in pieces:** a figure that has moved may move again with what is left of its Move until it attacks (`ActiveTurn.moves` in the engine); the play screen keeps such a figure chosen after a move (`canMoveOn`), and one that still has something to attack (`canAttack`, which counts targets it could turn to face), instead of handing the selection to the squad's next figure.
- **Draft filters:** the draft's cards use the unit gallery's controls (`ui/UnitFilters.tsx`: search, faction, type, attack and sort), plus **Only units I can draft**.
- **Draft map:** the draft opens on the battlefield (`screens/DraftMap.tsx`) until the first pick has been made; **Go to the draft** and **View map** switch views.

### Music
- **Moods:** `App.tsx` sets the scene (`useMusicScene` in `music.ts`): menu music outside a game, play music in the draft and the game, victory music once the game is over. The play screen brings in battle music while an attack is shown (`useBattleMusic`) and for `BATTLE_LINGER_MS` after. A round ending has no music of its own.
- **Blending:** `jukebox.ts` fades the old mood out, then the new one in (`BLEND_MS`). A mood's tracks play in turn: a fade out over the last `TRACK_FADE_MS`, `TRACK_GAP_MS` of quiet, then the next fades in. A mood that is left keeps its place; the victory music always starts from its beginning. Keep the jukebox free of timers and the DOM (it is moved on by `tick(now)`); it has unit tests.
- **Tracks:** `musicTracks.ts` lists them, and the files are in `apps/client/public/music` (MP3, all set to the same loudness). Use only CC0 or CC-BY music, never share-alike or non-commercial. A new track goes in `musicTracks.ts`, [docs/CREDITS.md](docs/CREDITS.md) and the test that matches the list to the files; the menu's Credits button reads the list.
- **Settings:** Music on or off and its volume are in `settings.ts`, set from the main menu (`.menu-sound`, placed by each style, with the Sounds box and slider) and from Display. Browsers allow no sound before the first click or key, so the music starts then.

### Sound effects
- **Playing one:** `playSound(id)` in `sfx.ts`; the sounds and their files are in `soundEffects.ts` (files in `apps/client/public/sfx`). Where a sound has several files, one plays at random, never the same twice running. A sound has a `gain` (keep the frequent ones quiet) and a `gapMs`; `exclusive` stops the last play first (the long dice roll).
- **Where each plays:** hops and landings through `Figures`' `onLand` (water and swamp splash, lava flares, `landingSound`), a dragged figure's landing when its move is made; the attack sound with the intro, wounds when the numbers float, the clatter with the destroyed figure's shake (all in `PlayScreen.tsx`); dice in `RollShow.tsx` as the attack dice are thrown and in `ThrownDice` (`scene/DiceTray.tsx`) as the defense dice follow; rounds and drafted or deployed units in `useEventSounds` (`App.tsx`), never for the events a game was opened with; other players' pings in `useOnlinePings`; hover (menu buttons, draft and gallery cards) and click (any button) by listening on the page.
- **Rules:** open licences only, as for the music; a new sound goes in `soundEffects.ts`, [docs/CREDITS.md](docs/CREDITS.md) and the test that matches the list to the files. Sounds start with the first click or key, play through the Web Audio API, and stop while the tab is hidden. Sounds on or off and their volume are in `settings.ts`, beside the music's.

### Main menu
- Four styles (War Table, Atlas, Banner Hall, Hex Command) share one set of choices and panels; `SetupScreen.tsx` builds them and `screens/menu/MenuFrame.tsx` and `menu.css` dress them. A new menu choice or setting goes in every style, and must fit the 1280 by 720 stage without scrolling (`e2e/menu.mjs` checks).
- **Map gallery and test game:** **Preview maps** in the Battlefield choice opens `screens/MapGalleryScreen.tsx` (every map in 3D, its start zones for each player count, **Play on this map** returns its id to the menu). The **Test game** choice (`testGame.ts`) loads a hot-seat game with two random 500-point armies already drafted and deployed on Twin Fords, all 11 glyphs and new-game rules, through `loadGame`.
- **Version:** the menu's corner shows "v1.0 · Last updated MM/DD/YYYY" (`version.ts`). The version is `version` in `apps/client/package.json` (1.0.0 shows as v1.0); change it only when the owner asks. The date is the latest commit's, read at build time, so it needs no editing.

### Browser tests
- **Hooks:** `apps/client/e2e` drives the canvas through `window.__aoh` (`scene/TestHook.tsx`, including `woundsShown()`), `window.__aohUi` (`PlayScreen.tsx`, including `introsSkipped()`), `window.__aohPingsHeard` (`online.ts`), `window.__aohMusic` (`music.ts`) and `window.__aohSfx` (`sfx.ts`); keep them working when changing those screens. A hook only removes `window.__aoh` if it still owns it, since a closing canvas can unmount after the next one mounts; after changing screens, tests wait for `window.__aoh?.canvas.isConnected`. Before clicking the canvas, tests wait for the camera to settle (`steadyCamera`, which includes `window.__aoh.cameraBusy()`). Tests that draft click **Go to the draft** first. After an attack, tests wait for the "Attack begins" intro to end (or `[data-pending]` to clear), as a click during it only skips it.
- **Known pitfalls:** read "Known pitfalls" and "Writing a browser test" in [docs/TESTING.md](docs/TESTING.md) before changing a browser test. When one fails because of the test rather than the game, add a row there in the same pull request as the fix.
- **Test mode:** every browser test sets `window.__aohTest` before the page loads (`src/testMode.ts`, `TEST_MODE`): the gaming table is drawn more simply, the camera keeps its older, narrower zoom limits, and the board draws at low graphics quality (`useGraphics`), unless the test also sets `window.__aohHighGraphics` (only `graphics.mjs` does). Players never have it. Keep test-only differences to these and list any new one in CLAUDE.md. Browser tests run with `reducedMotion: "reduce"`, and all but `full-game` set **Dice rolls** to None (an ordinary player setting) so the dice show does not cover the board.
- **Screenshots:** `E2E_SCREENSHOTS=<folder>` saves a run's screenshots, `E2E_FAILURE_SCREENSHOTS=<folder>` only a failure's (CI attaches them to a failed run).

## Testing

- `pnpm test` (Vitest): engine unit tests (`packages/rules/test`, with fixtures in `fixtures.ts`), content and balance tests, 12 random full-game simulations (3 with the online rules, 2 with hit zones) that check invariants and exact replays, protocol tests, server tests over real WebSockets (whole online games, pings, the shared skip of attack shows), and the client's figure model, table layout, 3D dice, fight-reading, hit shape, music player and sound effect tests.
- `pnpm e2e` (Playwright, needs `pnpm build` first): eight browser tests that drive the real interface. They reach the canvas through `window.__aoh` (projection, draw stats and a frame count, whether the camera is busy, how many wound numbers have floated; `scene/TestHook.tsx`) and `window.__aohUi` (current moves and targets, and the figure being dragged; `PlayScreen.tsx`), plus `window.__aohPingsHeard` (pings heard, set by `online.ts`) `window.__aohMusic` (the music's mood and track, set by `music.ts`) and `window.__aohSfx` (how often each sound effect was asked for, set by `sfx.ts`).
- CI (`.github/workflows/ci.yml`) runs only the checks a pull request's changes affect, chosen by `scripts/affected.mjs`, with each browser test as its own parallel job; pushes to `main` run everything. `deploy.yml` publishes the client to GitHub Pages on every merge to `main`, with `VITE_SERVER_URL` from the `GAME_SERVER_URL` repository variable.

[TESTING.md](TESTING.md) has what each browser test covers, what each kind of change runs, and how to write a browser test.
